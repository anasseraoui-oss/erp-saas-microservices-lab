Theme & Migration Guide
=======================

Purpose
-------
This short guide explains the centralized CSS theme we added (`src/Css/theme.css`), how to apply it in components, and recommended migration steps to modernize styling across the app.

Principles
----------
- Use CSS variables defined in `:root` and the `:root[data-theme="dark"]` or `.dark` overrides.
- Prefer variables over hard-coded colors; examples: `background: hsl(var(--background))`, `color: hsl(var(--foreground))`, `border-color: hsla(var(--border), 0.5)`.
- Provide smooth transitions for theme changes: `transition: background-color 180ms ease, color 180ms ease`.
- Create z-index tiers in the theme and use them via `var(--z-modal)`, `var(--z-dropdown)`.
- For module CSS that is scoped, prefer component-level `.modalContainer.dark` when the component toggles `dark` on its root element. Use `:global(.dark)` only when you toggle `.dark` on the document root (html). Match the mechanism used by the `DarkModeProvider`.

Quick migration steps (per component)
-----------------------------------
1. Identify hard-coded colors in the component CSS or module.
2. Replace with theme variables:
   - Backgrounds -> `hsl(var(--card))` or `hsla(var(--card), 0.9)`
   - Text -> `hsl(var(--foreground))`
   - Muted text -> `hsl(var(--muted))`
   - Borders -> `hsla(var(--border), 0.4)`
3. Ensure inputs use `--input-bg` and `--input-border`.
4. Use `min-height` and flex layout on card-like elements to prevent jumping when content changes.
5. Use `z-index` variables for overlays and modals and make modal backdrops `position: fixed; inset: 0; z-index: var(--z-modal);`.
6. Add `transition` for visual properties that change between themes.

Notes about `.dark` vs `data-theme="dark"`
-------------------------------------------
- The project currently uses `DarkModeProvider` which adds `.dark` and `data-theme="dark"` on the HTML element. There are two valid patterns:
  - Global root theme: add styles using `:global(.dark) .selector { ... }` so any scoped module picks up the theme when `.dark` is on `<html>`.
  - Component-local theme: component toggles `styles.dark` on its root element (e.g. `className={`${styles.modalContainer} ${isDarkMode ? styles.dark : ''}`}`) — in that case the module should include `.modalContainer.dark { ... }` selectors.
- Recommendation: prefer the global root approach for broad UI rules (colors, scrollbars, z-index tiers), but keep component-local `.modalContainer.dark` for small overrides where the component controls its own class.
